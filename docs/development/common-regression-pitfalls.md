# 常见错误与回归检查

适用于图片、视频渠道、游乐场、异步任务和计费。依据本项目已确认的问题整理，相关修改前必须阅读，完成前必须检查对应项。本文不替代根目录和 `web/AGENTS.md`、计费规则以及接口文档。

## 1. 可选字段不能无条件发送

已发生：游乐场文生图也发送 `images: []`，触发 `images must contain at least one reference image`。

- 文生图省略 `images`；图生图使用 `images: [{image_url: "https://..."}]`，支持多张参考图。
- 明确区分字段缺省、`null`、空数组、空字符串与显式零值；不能假设它们含义相同。
- 可选数值/布尔值转发遵循指针规则，保留显式 `0` 和 `false`。
- 修改请求构造时同时检查首次提交、重新生成、刷新后重新生成、API 客户端和 multipart 路径，不能只改当前点击入口。

回归：无参考图首次生成及重新生成均不发送 `images`；多图重新生成仍发送全部 URL；非法引用继续被后端拒绝。现有用例：`web/src/features/playground/components/media/__tests__/image-submission.test.tsx`。

## 2. 前后端类型通过不等于接口可用

已发生：异步任务用 multipart 提交却未正确识别模型；参考图字段与下游契约不一致；multipart 请求体消费后再次解析导致字段丢失。

- 逐项核对路由、鉴权、Content-Type、字段名、字段类型、模型映射和响应结构，以实际代码契约为准。
- 公共接口契约与供应商契约分开处理，由适配器转换；不要让客户端猜供应商字段。
- 请求体只能按可重用机制解析，文件及重复字段不能静默丢失。
- 调用失败后先检查 HTTP 状态与错误体，不能继续假设响应包含任务 `id`。
- 改接口时同步检查文档、游乐场和已知调用项目；没有验证的客户端不能声称已经适配。

回归：断言对外实际请求体和上游收到的请求，覆盖 JSON、multipart 单图/多图，以及提交失败不进入查询流程。

## 3. 后台任务不能假设仍有原始请求上下文

已发生：worker 缺少用户 ID 导致 `invalid userId`；游乐场任务错误调整令牌 0；执行时重复预扣。

- 从持久化任务恢复用户 ID、用户配置、分组及鉴权来源；检查上下文写入函数实际设置了哪些字段。
- 区分会话用户和 API 令牌任务，不对不存在的令牌记账。
- 任务入库再执行的路径必须验证，不能只测试内存里直接调用 worker。
- 后台恢复必须使用任务的计费快照；不得偷偷改用执行时管理员的新价格。
- 私有任务数据不保存可用认证头；对用户返回的错误使用现有脱敏机制。

回归：普通用户游乐场/API 两种入口，任务创建后重新加载并执行；覆盖管理员改价、成功、失败、重复收尾和凭据脱敏。

## 4. 预扣、结算和退款必须检查完整链路

已发生：按次误乘秒数；默认计费时长与上游请求不一致；部分图片返回仍按请求张数计费；失败退款减去了尚未增加的已用额度。

- 修改前完整阅读 `.agents/rules/billing.md`，涉及表达式时阅读 `pkg/billingexpr/expr.md`。
- 按次/按秒必须遵循配置；上游有效时长、默认值、模型映射与估算保持一致。
- 请求值、别名、metadata、透传字段和 multipart 都要检查数量边界，不能让合法别名掩盖另一个非法字段。
- 区分请求张数与实际返回的有效图片数；结算和任务记录使用实际计费结果。
- 预扣一次；结算补退差额；失败只退实际预扣；已用额度只撤销已经累计的部分。
- 使用集中安全额度转换和审计机制，禁止裸数值转换及负扣费。

回归：同一渠道按次/按秒、缺省/边界/非法时长、部分返回、失败退款及重复终态；核对钱包、令牌、用户/渠道已用额度、任务额度和消费日志，而非只断言 HTTP 成功。

## 5. 历史持久化不能只检查保存函数

已发生：自动截断 24 条；缓存重置删掉用户隔离历史键；刷新后 File 对象丢失导致无法重新生成；一个字段类型变化使工作区整体加载失败。

- 同时检查写入、读取 schema、迁移、缓存清理、用户隔离和删除入口。
- 除用户明确删除/清除外，不主动截断或清空图片、视频历史。
- 重新生成依赖持久化 URL 和参数，不能依赖刷新后丢失的 File 或内存映射。
- 后端允许的数字/字符串进度和可空结果必须与存储 schema 对齐；保存影响生成行为的模式参数。
- 本地历史记录与远程素材有效期是不同保证；不能声称本地记录能永久保存远程媒体内容。

回归：超过旧上限、刷新、缓存重置、不同用户隔离、无/单/多参考图、允许的可空响应，以及用户主动清除。

## 6. 一个任务失败不能阻断其他任务

已发生：`Promise.all` 中单项失败导致全部轮询结果丢弃；固定 interval 造成未结束请求重叠。

- 独立任务分别接收成功或失败结果；本轮完成后再安排下一轮。
- 组件卸载时清理调度；终态任务停止轮询。
- 创建请求的加载状态与后台任务状态分开，提交成功进入历史后允许继续提交。
- 前端时长选项与后端实际模型能力一致，不能从相似模型复制参数。

回归：同时存在成功/失败/进行中任务、刷新恢复轮询、提交后继续提交，以及渠道特有的时长选项。

## 完成前检查

1. 先写能复现当前缺陷的失败用例，再修复；优先补到已有对应测试，不复制生产逻辑计算期望值。
2. 检查相邻入口和相反条件：有参考图/无参考图、首次/重新生成、会话/API、成功/失败，而非只验证报错的一条路径。
3. 在真实请求或存储边界断言行为；mock 上游成功不代表生产供应商已验证。
4. 运行受影响测试、相关检查和 `git diff --check`。前端改动运行类型检查及改动文件 lint；模块、数据库、计费等额外验证按项目规范执行。
5. 只报告实际执行并通过的验证，明确未验证边界；文档不能替代测试，也不能保证没有潜在缺陷。
6. 新确认的重复性问题补充“触发条件、错误原因、防范规则、回归场景”；已有条目补全即可，不重复增加清单。
